# /docs Implementation Plan

> **For agentic workers:** execução por terminais Collie em paralelo (dono escolheu): 1 designer, 1 dev, 4 escritores;
> o Shepherd integra e verifica. Steps em checkbox.

**Goal:** `/docs` e `/pt/docs` com 24 páginas em Markdown, sidebar, "Nesta página" e anterior/próximo, no visual do site.

**Architecture:** Arquivos `content/docs/<locale>/<group>/<page>.md` lidos no build por `src/lib/docs.ts` (reaproveita o
frontmatter e o `toSegments` do blog), ordem da sidebar em `src/i18n/docs-nav.ts`, rota catch-all estática por locale.

**Tech Stack:** Next 16.4 (export estático), `marked`, blocos de `src/lib/blocks.ts`, Tailwind, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-28-docs-design.md`

## Global Constraints

- Nenhuma dependência nova.
- Conteúdo só do app na tag `v0.3.1` (`git show v0.3.1:<arquivo>` em `~/Documents/codes/my-orchestrator-memory`); nada de
  `main` local nem de spec de design.
- Toda página existe em `en` e `pt` com o mesmo caminho; falta de um lado falha o build.
- Blocos: só os de `docs/blog-blocks.md` (`callout`, `stats`, `steps`, `compare`, `tabs`).
- Rótulos de UI do app como estão no app (PT); nomes próprios (Vizinho, field) não se traduzem.
- Visual: tokens de `src/app/tokens.css`, Dark e Light, 1440 e 390 sem rolagem horizontal.

## Review Focus

- Página listada em `docs-nav.ts` sem arquivo (ou arquivo sem entrada na nav) → build falha com o caminho.
- Título com acento/pontuação vira âncora estável (`## Sandbox e rede` → `#sandbox-e-rede`), igual nos dois locales só se o
  texto for igual (ok divergir).
- Bloco inválido numa página de docs falha o build como no blog (`<locale>/<path>.md:<linha>`).
- `/docs` e `/pt/docs` sem slug respondem (primeira página da nav).
- Página longa (referência da CLI) com código largo não rola a página no 390.

### Task 2: Leitura e validação (dev)

leitor de frontmatter genérico, se preciso).

**Interfaces (Produces):**
- `type DocMeta = { title: string; description: string; status?: "preview"; since?: string }`
- `type DocNavGroup = { id: string; title: Record<Locale, string>; pages: string[] }` e `docsNav: DocNavGroup[]` em
  `docs-nav.ts` (pages = `"<group>/<page>"`, na ordem da tabela acima).
- `getDoc(locale: Locale, slug: string, opts?: { root?: string }): { meta: DocMeta; segments: Segment[]; toc: { id: string; title: string; depth: 2 | 3 }[] }`
- `docSlugs(): string[]` (achatado da nav), `docNeighbors(slug): { prev?: string; next?: string }`
- `assertDocs(opts?: { root?: string }): void` — lança com a lista de problemas: arquivo faltando por locale, arquivo
  sem entrada na nav, `title`/`description` vazios.
- Âncora: `slugifyHeading(text): string` (minúsculas, sem acento via `normalize("NFD")`, não-alfanumérico → `-`).

- [ ] Testes (`node --test`), com raiz temporária como em `blog.test.ts`:
  `assertDocs` lança "pt/features/fields.md missing" quando só existe o en; lança para arquivo fora da nav;
  `getDoc` devolve `toc` `[{id:"sandbox-e-rede",title:"Sandbox e rede",depth:2}]` para `## Sandbox e rede` e o `h2` sai
  com `id="sandbox-e-rede"`; bloco inválido lança com `pt/features/fields.md:<linha>`; `docNeighbors` do primeiro não tem
  `prev`.
- [ ] `npm test` falha, implementar, passa. Commit.
